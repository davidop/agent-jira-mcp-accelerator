# Phase 4.1: App image publication to ACR - Context

**Gathered:** 2026-05-28
**Status:** Ready for planning
**Source:** .planning roadmap + current deploy workflow + infra baseline

<domain>
## Phase Boundary

This phase establishes deterministic image publication for runtime services by building and pushing OCI images from the three .NET service projects into Azure Container Registry (ACR).

The phase is deployment-artifact focused. It does not require runtime release to Container Apps.

</domain>

<decisions>
## Implementation Decisions

### Publication scope
- Publish container images for `Agent.Api`, `Jira.McpServer`, and `Web`.
- Use .NET SDK container publishing (`dotnet publish /t:PublishContainer`) to avoid introducing Dockerfile maintenance in this phase.

### Registry target
- Use the provisioned ACR (`entagentaccelacr`) as the single registry target.
- Resolve login server dynamically from Azure to avoid hardcoded endpoints.

### Tag strategy
- Use commit SHA (`GITHUB_SHA`) as the primary immutable tag for traceability.
- Verification checks require repository tag presence after publish.

### Pipeline order
- Keep infra provisioning first.
- Publish images only after ACR existence is verified.

### Verification stance
- Add an explicit gate that fails when expected repositories have no tags.
- Keep scope limited to image publication success and registry artifact visibility.

### the agent's Discretion
- Exact step names and shell implementation details in GitHub Actions.
- Optional secondary tags (for example, `latest`) are deferred unless required by runtime rollout.

</decisions>
