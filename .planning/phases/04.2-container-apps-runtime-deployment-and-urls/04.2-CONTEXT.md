# Phase 4.2: Container Apps runtime deployment and URLs - Context

**Gathered:** 2026-05-28
**Status:** Ready for execution
**Source:** .planning roadmap + deploy workflow + Bicep runtime resources

<domain>
## Phase Boundary

This phase deploys runtime services to Azure Container Apps using ACR-published images and validates externally reachable service URLs.

The phase starts after image publication and focuses on runtime deployment and endpoint verification.

</domain>

<decisions>
## Implementation Decisions

### Runtime resources
- Use Bicep to define runtime resources controlled by `deployApps`.
- Runtime stack includes Log Analytics, user-assigned managed identity, ACR pull role assignment, Container Apps Environment, and three Container Apps.

### Service topology
- Deploy three apps:
  - `ent-agent-accel-api`
  - `ent-agent-accel-mcp`
  - `ent-agent-accel-web`
- Each app uses external ingress on port 8080.

### Release linkage
- Use `GITHUB_SHA` as image tag passed to runtime deployment parameters.
- Runtime deployment is executed after ACR publication and tag checks.

### Verification stance
- Add `az deployment group what-if` before runtime apply.
- Validate ingress FQDN for all three apps and print URLs in workflow logs.

### the agent's Discretion
- Keep runtime verification in deploy workflow (not separate script) for single-pipeline observability.
- Keep networking and security hardening beyond baseline out of this phase.

</decisions>
